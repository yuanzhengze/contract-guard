# 产品规划：合同哨兵（ContractGuard）

> AI 合同风险审查助手 · 面试 Demo · v0.1（一晚交付）
> 开发方式：AI Native —— PM 定义问题、决策与验收标准；AI Agent 完成全部实现与自测。

---

## 1. 一句话定位

**让没有法务的小团队，1 分钟看懂一份合同哪里会坑自己，并知道该怎么改。**

## 2. 问题与机会

| 维度 | 现状 |
|---|---|
| 谁痛 | 中小企业老板、商务、采购、HR、自由职业者 —— 每月签 5–50 份合同，没有专职法务 |
| 现在怎么做 | ① 直接签（风险最大）② 找外部律师（单份 500–3000 元，1–3 天）③ 丢给通用 AI 聊天（回答笼统、无结构、不对照原文、不敢信） |
| 核心痛点 | 看不懂哪里有坑；不知道多严重；不知道怎么改；结论没法留档给老板/同事 |
| 机会 | 大模型已能读懂长合同，但“聊天”形态不适合审查任务 —— 缺 **结构化、可溯源、可行动** 的产品层 |

**核心洞察：用户要的不是“和合同聊天”，而是“一份带原文定位的体检报告 + 一个能追问的顾问”。** 这是本产品与“把 PDF 扔给通用 AI”的根本区别。

## 3. 目标用户

**主角 Persona：小周，28 岁，30 人科技公司的商务经理**
- 每周处理 3–5 份采购 / 服务 / 租赁合同，公司没有法务
- 怕签错担责，但请律师又慢又贵
- 诉求：快速知道「哪几条要注意 → 为什么 → 让对方改成什么」，并把结论发给老板

**v0.1 非目标用户**：专业律师（需要法条检索与批注工作流）、大企业法务部（需要私有化与审批流）。

## 4. 核心用户旅程

```
打开网页 → 上传合同 PDF（或一键「使用示例合同」）
       → 审查进度（解析 → 切分条款 → 逐类检查 → 生成报告），30–60 秒
       → 风险报告：安全评分 + 高/中/低风险计数 + 一句话总评
            左：合同原文（风险句按等级高亮）   右：风险卡片列表
            点卡片 ↔ 原文定位（双向联动）
       → 对某条风险「追问」/ 自由提问 → 流式回答，引用条款号
       → 一键导出审查报告（发给老板 / 对方）
```

## 5. 功能范围（MoSCoW）

### Must（今晚必须交付）
1. **上传 PDF**：拖拽/点击，≤10MB，文本型 PDF；首页提供「使用示例合同」
2. **自动风险审查**：上传即开始，无需提问；按 10 类风险清单逐项检查
3. **结构化风险卡片**：等级 / 类别 / 原文引用 / 风险说明 / 修改建议
4. **原文对照**：左侧原文，风险句按等级着色高亮；卡片与原文双向定位
5. **风险总览**：0–100 安全评分 + 各等级计数 + 一句话总评
6. **追问（RAG + 流式）**：自由提问或卡片一键追问；检索相关条款作上下文；回答标注引用条款；逐字流式输出
7. **导出报告**：一键导出可打印的 HTML 报告（浏览器可另存 PDF），含免责声明
8. **真实效果，无演示模式**：所有审查与追问均由真实大模型生成；失败时给出明确错误与重试入口，不用假数据掩盖

### Should（时间够就做）
- 审查分步进度文案（“正在检查付款条款…”）
- 3 个预设快捷追问
- 埋点（上传、审查完成、追问、导出）写入本地日志，并提供 `/api/metrics` 汇总

### Won't（v0.1 明确不做 → 路线图）
账号与付费 · 扫描件 OCR · Word 格式 · 多合同对比 · 自定义审查规则 · 团队协作批注 · 移动端深度适配

## 6. 风险审查清单（产品核心资产）

| # | 类别 key | 名称 | 检查要点 |
|---|---|---|---|
| 1 | payment | 付款条款 | 账期过长、预付比例、逾期付款责任是否对等 |
| 2 | liability | 违约责任 | 违约金畸高/畸低、责任只约束我方 |
| 3 | termination | 解除与终止 | 对方单方任意解除权、我方解除条件苛刻 |
| 4 | renewal | 自动续约 | 默认续约、续约涨价、退出通知期过长 |
| 5 | indemnity | 责任限制与赔偿 | 我方无限责任、对方责任上限过低、间接损失 |
| 6 | ip | 知识产权 | 成果归属、我方既有 IP 被转让 |
| 7 | confidentiality | 保密条款 | 单方保密义务、期限不合理 |
| 8 | dispute | 争议解决 | 管辖地在对方所在地、仲裁/诉讼选择 |
| 9 | acceptance | 交付与验收 | 验收标准模糊、逾期视为验收 |
| 10 | other | 其他不公平条款 | 单方变更权、免责过宽、排他/竞业限制 |

**风险等级**
- 🔴 高 high：可能造成重大损失或丧失关键权利 —— 签前必须修改
- 🟠 中 medium：明显对我方不利 —— 建议协商修改
- 🟢 低 low：表述不清或可优化 —— 知悉即可

**安全评分 = 100 × 0.85^高 × 0.93^中 × 0.98^低**（每个高风险扣当前分 15%，中 7%，低 2%）。
由规则计算而不是让 AI 打分：可解释、稳定、同一份合同每次结果一致。
> 决策（实测后调整）：最初用线性扣分（100−15×高−7×中−2×低），实测示例合同 7 高 4 中直接得 0 分——既像 bug，也让所有“很差”的合同失去区分度。改为乘法递减后同一合同得 24 分。

## 7. 关键产品决策（面试重点）

| 决策 | 选择 | 理由 |
|---|---|---|
| 形态 | **网页端，桌面优先** | B 端审合同在电脑上；双栏对照需要大屏；面试官点链接即用 |
| 审查 vs 追问 | **审查走全文，追问走 RAG** | 审查要求“不漏”，合同多数 <30 页，全文进上下文召回最高；追问要求“准且快”，检索相关条款降成本、降幻觉、可给引用 |
| 检索方案 | **条款级切分 + 本地 BM25（中文二元分词）**，不用向量库 | 合同天然按“第 X 条”结构化，条款级切分比固定长度切块更贴语义；法律术语关键词命中率高；去掉 Embedding/向量库依赖，零成本部署、一晚可交付。路线图：升级混合检索 |
| 输出约束 | **强制 JSON → 卡片** | 结构化才能定位、计分、导出；把“不可控的 AI 回答”变成可控的产品组件 |
| 可信度 | **每条风险必须引用原文，后端校验引用真实存在** | 防幻觉：无法在原文中定位的引用标记为“未定位”并在 UI 中提示 |
| 模型 | **GLM-5.3（OpenAI 兼容接口）** | 中文法律文本理解好；兼容接口，可一键切换其他模型 |
| 真实性 | **不做演示/预置模式** | Demo 的说服力来自真实效果；用评测脚本量化召回率，而不是用假数据保证好看 |
| 合规 | **全局免责声明 + 文件不落盘** | 法律类 AI 产品的底线 |
| 对开源项目 | **借鉴架构，不沿用代码** | `ai-pdf-chatbot-langchain` 已停止维护，依赖 Supabase + LangGraph Server + OpenAI，一晚内配通并改造的成本高于重写；保留其“摄入 → 检索 → 流式生成”的核心链路 |
| 技术栈 | **Node + Express + 原生前端（无构建）** | 运行环境零编译依赖、启动即用、部署简单；Demo 阶段速度优先于工程化 |

## 8. 成功指标

**北极星指标**：每周完成「审查 → 追问或导出」的合同数（代表用户真正基于结论做了决策）

| 层级 | 指标 | Demo 目标 |
|---|---|---|
| 体验 | 上传到出结果时间 | < 90 秒 |
| 质量 | 示例合同预埋风险点召回率 | ≥ 7/8 |
| 质量 | 引用可定位率 | ≥ 90% |
| 参与 | 追问率 = 追问会话 / 完成审查会话 | 可观测 |
| 转化 | 导出率 = 导出次数 / 完成审查会话 | 可观测 |

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| AI 幻觉 / 漏判 | 固定清单逐类检查；引用原文校验；免责声明；路线图：律师复核增值服务 |
| 隐私顾虑 | 文件仅内存处理不落盘、会话 1 小时过期；路线图：私有化部署 |
| 扫描件无法解析 | 提取文字过少时提示“暂不支持扫描件” |
| 超长合同 | v0.1 限 60,000 字，超出提示；路线图：分段审查合并 |
| 现场演示失败 | 提前跑评测确认模型可用 + 录屏备份 + 失败可一键重试 |

## 10. 商业化与路线图

- **定价设想**：免费 3 份/月 → 个人版 29 元/月 → 团队版 99 元/人/月（自定义清单、协作、历史库）→ 律师复核按次加购
- **路线图**：v0.2 账号/历史/Word/OCR → v0.3 企业自定义审查清单、合同版本对比 → v1.0 协作批注、审批流、私有化
- **竞品差异**：通用 AI（无结构、无定位）｜专业法务产品（面向律师、重、贵）→ 我们：**面向非法务人群的轻量“合同体检”**
